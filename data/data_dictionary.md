# Data Dictionary

## Raw Dataset Variables

| Variable | Expected type | Business meaning | Planned use | Validation checks |
|---|---|---|---|---|
| `InvoiceNo` | String | Identifier assigned to an invoice or transaction | Count orders and identify cancellations | Missing values, format, cancellation prefix and repeated invoices |
| `StockCode` | String | Identifier assigned to a product | Product-level analysis | Missing values, unusual codes and inconsistent formats |
| `Description` | String | Product name or description | Product reporting and interpretation | Missing values, blank values and inconsistent descriptions |
| `Quantity` | Integer | Number of units recorded for the product line | Revenue calculation and quantity analysis | Zero values, negative values, returns and extreme quantities |
| `InvoiceDate` | Datetime | Date and time when the transaction was recorded | Recency, monthly trends and retention analysis | Missing values, invalid dates and date range |
| `UnitPrice` | Decimal | Price of one product unit in pounds sterling | Revenue and order-value calculations | Negative values, zero values and extreme prices |
| `CustomerID` | String | Identifier assigned to a customer | Customer-level aggregation and segmentation | Missing values, invalid formats and inconsistent types |
| `Country` | String | Country associated with the customer | Geographic analysis | Missing values, inconsistent names and unexpected categories |

## Dataset Grain

One row represents one product line within an invoice.

An invoice containing five products may therefore appear as five rows with the same `InvoiceNo`.

This distinction is important:

- Number of rows is not equal to number of orders.
- Unique `InvoiceNo` values represent invoices.
- Unique `CustomerID` values represent identifiable customers.
- Revenue must first be calculated at line level before aggregation.

## Planned Derived Variables

| Derived variable | Definition | Purpose |
|---|---|---|
| `LineRevenue` | `Quantity × UnitPrice` | Revenue contributed by each transaction line |
| `InvoiceDateOnly` | Date extracted from `InvoiceDate` | Daily analysis |
| `InvoiceMonth` | Month extracted from `InvoiceDate` | Monthly reporting |
| `InvoiceYearMonth` | Year and month in `YYYY-MM` format | Time-series grouping |
| `IsCancellation` | Invoice number starts with `C` or `c` | Cancellation identification |
| `IsValidSale` | Positive quantity, positive price and non-cancelled invoice | Separate completed sales from cancellations or returns |
| `OrderRevenue` | Sum of line revenue for each invoice | Order-level revenue |
| `CustomerFirstPurchase` | Earliest valid purchase date for each customer | Cohort and lifecycle analysis |
| `CustomerLastPurchase` | Most recent valid purchase date for each customer | Recency calculation |
| `Recency` | Days since the customer's latest purchase | RFM segmentation |
| `Frequency` | Number of unique valid invoices per customer | RFM segmentation |
| `Monetary` | Total valid revenue generated by each customer | RFM segmentation |
| `CustomerOrderCount` | Number of unique valid orders per customer | Repeat-purchase analysis |
| `IsRepeatCustomer` | Customer has more than one valid order | Repeat-customer classification |
| `CustomerSegment` | Segment assigned using RFM rules | Customer prioritisation |
| `DaysSinceLastPurchase` | Difference between analysis date and last purchase | Inactivity and risk analysis |
| `IsInactive` | Customer exceeds the selected inactivity threshold | Retention targeting |

## Planned Aggregation Levels

### Transaction-line level

Used for:

- Data-quality checks
- Product quantities
- Unit prices
- Returns
- Cancellations
- Line revenue

### Invoice level

Used for:

- Total orders
- Order revenue
- Average order value
- Products per order

### Customer level

Used for:

- Customer revenue
- Purchase frequency
- Repeat purchasing
- RFM segmentation
- Inactivity analysis

### Time level

Used for:

- Monthly revenue
- Monthly customers
- Monthly orders
- Purchase trends
- Retention indicators

### Country level

Used for:

- Revenue by country
- Customers by country
- Orders by country
- Average order value by country

## Currency

`UnitPrice`, `LineRevenue`, `OrderRevenue` and `Monetary` will be treated as pounds sterling because the source dataset records unit prices in sterling.

No currency conversion will be performed in the initial MVP.
